# Stage 4 initial baseline evidence

This is a preliminary baseline, not the final successor validation. The original stdio run was interrupted after 1,378 paired cases; its files remain at `/tmp/ferrum-stage4-808-results-stdio`. A separate run of the remaining 134 cases is at `/tmp/ferrum-stage4-808-results-remaining`. Together they cover exactly the 1,512 selected keys, without duplicate, missing or unexpected keys. Every selected source file matches its frozen SHA-256 and each recorded pair matches its manifest selection. Both run manifests and raw results are preserved. [compatibility-baseline.json](compatibility-baseline.json) contains the recomputed per-case observations, differences, input hashes and artifact paths; the local `/tmp/ferrum-stage4-baseline-report/build_report.py` reproduces it without modifying either run.

The recomputation uses the current classifier, byte-identical to `ca60bf2`'s `tools/compatibility_evidence.py`. Results: 650 both verified; 836 both failed with the same error ID/position multisets; 10 had different ID/position multisets; 16 were inconclusive. All 1,512 pairs have the legacy runner’s `completed_batch` label, with no selected isolated retries. That driver did not invalidate sessions containing prover-interaction faults, so this label does not establish clean reuse for those sessions. The successor driver stops on such faults and retains failed sessions separately from isolated retries. A timeout or infrastructure error is inconclusive, not a verification failure. An ID/position match does not imply message, warning, phase, or order equality.

The ten ID/position mismatches comprise eight ADT cases, `quasihavoc/havoc_impl4.vpr`, and `conditionalizePermissions/silicon_0008.vpr`. Candidate ADT, havoc, conditional-position and warning fixes are pending successor validation; none is claimed to change this baseline. Across the 1,512 pairs, 69 differ in the error ID/position/message multiset, 99 in ordered warning lists, and eight in normalized phase. The runner's `same_error_order` compares entire error records, so its 69 false values do not by themselves prove an ordering difference. The eight phase differences all report source consistency check versus native prepare-verification (three termination, three SIF, two ARP). Detailed records and actual strings are retained in JSON.

Review of the 69 message-tuple differences: 24 are whitespace-only pretty-printer differences, nine are import I/O wording, 17 parser-engine or macro-expansion messages, eight involve timeout or infrastructure outcomes, eight ADT diagnostics, one havoc diagnostic, one conditional position, and one generated type-variable number (`mask_heap/.../comparisons_fail.vpr`). These are categories of observed differences, not a declaration that all are semantically interchangeable. Warnings include missing prefixes or positions, differing positions, and additional or missing warnings; exact lists remain in JSON.

There are 11 source and 11 native timeout observations, and five source `prover.interaction.failed` observations (all listed with full messages and session paths in JSON). Fresh isolated runs using frozen stdio settings gave both-verified for longest-common-prefix and parallel two-worker tree-delete-min, and both-timeout for testTreeWandE1 and index-shifting. A separate graph-marking → longest-common-prefix reused session reproduced source timeout then `global-decls` prover failure; native timed out then verified. These observations support an association with that session sequence, not a proven root cause or general reuse compatibility. Raw replay evidence remains in the paths listed in JSON; the original errors are not replaced by isolated results.

The 26-case linked Z3-API and branch-two profiles each recorded nine both-verified and 17 same-ID/position pairs, with completed batches and no retries; these are representative profiles, not full-corpus results. Of 18 original timeout controls, 15 passed and three native timeout-then-valid controls did not induce the expected timeout. Three additional native timeout-then-valid controls, using a different timeout fixture, passed across stdio, branch-two and linked profiles. The controls establish only those specific observations; they do not supersede the session fault evidence.

The frozen archive is Ferrum `808efa6455ee1299ce4ad70b56c86e9dbb12556e`, with production backend at `5cbb29be28b45194e555d2e173ed39b1a64a80de`. The source revisions, settings, binaries, inventory and selected artifacts are recorded by the frozen evidence files and their hashes in JSON. A full 1,512-case successor run after runtime fixes remains required.
